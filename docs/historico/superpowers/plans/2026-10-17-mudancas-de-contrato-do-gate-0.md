## Measured facts (source of truth: docs/gate-0-resultado-2026-10-17.md and docs/gate-0-capturas/)

- eSCL works on this unit, through two routes with the **same UUID**:
  - USB: macOS IPP-over-USB bridge, advertised by mDNSResponder **only on interface kDNSServiceInterfaceIndexLocalOnly (0xFFFFFFFF)**, host target `localhost.`, dynamic port (57805 today). Not subject to macOS Local Network privacy.
  - Wi-Fi: host `<printer-host>.local.`, port 8080 (HTTPS `_uscans` on 443, unused).
- **python-zeroconf cannot see the USB route** (tested with zeroconf 0.151.5: it returned only the Wi-Fi record; its `parsed_addresses()` also returned IPv6 addresses despite `IPVersion.V4Only`). The native `dns_sd` API (libSystem, via `ctypes`) sees both routes: working reference `docs/gate-0-capturas/dns-service-discovery-probe.py`.
- `POST ScanJobs` → 201 with an **absolute** `Location` (`http://localhost:57805/eSCL/ScanJobs/<uuid>`); job ids are UUIDs.
- `GET <job>/NextDocument` **blocks until the image is ready** (72 s for A4 600 dpi colour) and answers 200 on the first request; then 404.
- `DELETE <job>` after the final 404 answers **404** (the job is already gone).
- After delivering the image, `ScannerStatus` is `Processing` for 4–5 s, then `Idle`.
- The JPEG already carries the right JFIF density (300 or 600).
- Real capabilities and status XML (redacted serial/UUID/host): `docs/gate-0-capturas/hp-deskjet-2800-scanner-capabilities.xml`, `docs/gate-0-capturas/hp-deskjet-2800-scanner-status-idle.xml`.
- Cycle times: ~10 s grayscale 300 dpi, ~19 s colour 300 dpi, ~77 s colour 600 dpi.

## Follow-up contract changes (after the first fix pass, 2026-10-17)

| ID | Change | Spec place | Tasks |

| G0C-14 | **Route is classified by host, not only by interface.** The capture shows mDNSResponder also resolving the USB instance to `localhost.:57805` on the Wi-Fi interface (11). Rule: a record is `USB` when its interface index is 0xFFFFFFFF **or** its normalized host name is a loopback name (`localhost`, `127.0.0.1`, `::1`, case-insensitive); otherwise `NETWORK`. Add the pure function `classify_route(interface_index: int, host_name: str) -> ScannerRoute` to `dns_service_discovery_record_source.py` (unit-tested). `BonjourScannerDiscovery.discover` **deduplicates endpoints by `base_address`** (first occurrence wins, after USB-first ordering). | 6.2 | T9 |
| G0C-15 | **Fresh discovery once per process, and the saved endpoint is only a fallback.** The first `acquire_gateway` (and the first `check_connection`) of a process, and every `refresh`, runs discovery and picks by the G0C-4 preference order using the saved UUID; the saved endpoint is used directly only when discovery returns nothing. After that, the in-memory gateway is reused; when a status check on it fails, rediscover (same preference) before raising `ScannerUnreachableError`. Consequence: plugging the USB cable in is picked up at the next app start or by "Procurar de novo" (refresh), and a saved Wi-Fi endpoint never pins the app to Wi-Fi across restarts. Save the chosen endpoint after every successful pick. | 6.4 | T9, T14 hardware/integration expectations if they assert discovery counts |
| G0C-16 | **Manual addresses on loopback are USB.** `use_manual_address(base_address)` stores `route = ScannerRoute.USB` when the address host is a loopback name (same rule as G0C-14, through a shared pure helper, e.g. `route_for_host_name(host_name) -> ScannerRoute` in `domain/scanner_route.py`, reused by `classify_route`), otherwise `NETWORK`. | 6.4 | T2 (helper in the enum module, unit-tested), T9 |
